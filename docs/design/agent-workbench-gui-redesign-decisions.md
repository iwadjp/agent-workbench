# GUI設計 選択ログ — Agent Workbench プロジェクト一覧+詳細画面

対象: agent-workbench のプロジェクト一覧+選択中プロジェクト詳細画面(Webローカルツール)
維持する機能: 複数targetのrepo一覧、Git状態、放置日数、PROGRESS、Agent context、Development session
不満点(初期): 上部の情報が多すぎる / 一覧から再開操作まで遠い / 詳細情報が古くなりがち

---

## Round 1

提示した3案:
- 案A: 折りたたみ要約 + インライン展開(行クリックで直下にアコーディオン展開)
- 案B: 分割ビュー(左に一覧、右に選択中repoの詳細を固定表示、常時見える再開ボタン)
- 案C: 優先度ファースト(「次に再開する」候補カード + 詳細はドロワー表示)

選択結果:
- **採用ベース**: 案B(分割ビュー・固定詳細ペイン)
- **借用**(次案に統合する部分):
  - 案Aより: 一覧の行から直接「再開」できるボタン(詳細を開かずに起動)
  - 案Cより: 「次に再開する」候補カードを上部に提示する仕組み
- **保留**(Round2で振る軸): 上部統計情報(25 repos / clean / dirty 等)をどこまで残すか
- **却下**: 詳細をドロワー(オーバーレイ)で重ねて表示する方式 → 常時表示の固定ペインを優先するため不採用

## Round2で固定する構成(確定事項)

- レイアウト: 左に repo 一覧、右に選択中 repo の詳細を固定表示(スクロールしても常に見える)
- 一覧の各行に「▶再開」ボタンを直接配置(1クリックで起動、詳細を開かずに済む)
- 一覧の上部に「次に再開する」候補カード(優先度上位3件、各カードにも再開ボタン)
- 詳細表示はドロワーではなく右の固定ペイン方式のみ使用

## Round2で振る軸(保留 → 3案で比較)

上部統計情報の扱い:
- 案B1: 統計を表示しない(「次に再開する」候補で代替)
- 案B2: 要対応項目のみ最小限バッジで1行表示
- 案B3: 折りたたみ式(デフォルト非表示、トグルで全項目表示)

---

## Round 2

提示した3案: 案B1(統計非表示) / 案B2(要対応のみ最小バッジ) / 案B3(折りたたみ式・全項目)
共通(確定のまま): 分割ビュー ・ 一覧行から直接再開 ・ 次に再開する候補カード ・ 詳細は右固定ペイン

選択結果:
- **採用ベース**: 案B2(要対応項目のみ最小バッジ表示)
- **借用**: 案B3の「必要な時だけ全統計を展開できる小さなリンク」
- **却下**: 案B1(統計の完全非表示) / 案B3の全項目を主役にする構成

## Round3で確定する最終仕様

- 通常時は dirty / untracked / abandoned など**要対応項目のみ**を1行バッジで表示する
- 要対応項目が0件のときは統計行自体を非表示にする(トグルリンクも含めて出さない)
- clean / active / dogfooding / released など全件数はデフォルトでは表示しない
- 全統計は「詳細統計」リンクから折りたたみ表示で見られるようにする(要対応が1件以上あるときのみリンクを出す)
- レイアウトは分割ビュー(左:一覧、右:選択中repoの詳細を固定表示)
- 一覧の各行に「▶再開」ボタンを直接配置し、詳細を開かずに起動できる
- 一覧上部に「次に再開する」候補カード(優先度上位3件、各カードにも再開ボタン)を表示する
- 詳細はドロワーではなく右の固定ペインに表示する

Round3(最終)ではこの構成に対する比較案の提示は行わず、上記を1つの最終デザインとして実装する。

## Round 3 修正: 詳細ペイン仕様の差し替え

Round3の初回final_design.htmlは、詳細ペインを簡略化しすぎて現行Agent Workbenchの実機能(latest tags/remote/scan diagnostics/Development session settings/Handoff/Documents/Context/Project status & note等)の多くが欠落していることが判明。現行の詳細画面(スクリーンショット)を基準に再確認し、以下へ差し替えた。

**維持(Round3外枠の確定事項、変更なし)**:
- 次に再開する候補カード
- 要対応項目のみの統計行(0件時は行ごと非表示)
- 左一覧+右固定詳細ペインの分割ビュー
- 一覧行から直接「▶再開」

**差し替え(詳細ペインの内部構造)**:
- 却下: フラットな4カード構成(Freshness/Latest commit/Next action/Development sessionのみ)
- 採用: 固定ヘッダー + 固定要約 + 3タブ(Resume / Documents / Diagnostics)構成。現行の全機能をいずれかのタブまたは固定要約に再配置し、削除しない。

詳細な対応表は `implementation_spec.md` に記載。

## Round 3 実機修正: 一覧性の回復

commit `849653a` の実機確認で、右詳細ペインを追加した代償に左一覧と上部の情報密度が現行より大きく後退していた（上部にWSLエラー/Targets/候補カード/統計/検索が縦積みで一覧開始位置が下がる、左ペインが狭くrepo名・branch・latest commit・変更・R/Pが見えない、未選択時に右へ巨大な空白）。

最重要方針: **右詳細ペインを追加する代わりに、左一覧の比較性能を犠牲にしない。**

修正の要点（詳細は PROGRESS.md）:
- 左一覧を現行の横長テーブル（全列）へ復元し、「再開」は専用列の右端ボタンに（repo名直後には置かない）。
- 未選択時は一覧を全幅表示（右ペイン非表示）、repo選択時のみ 左65% : 右35% の分割ビュー。
- 「次に再開する」は横1行のコンパクトなchipへ。
- WSL/接続エラーとTargets（スキャン詳細）は1行要約＋折りたたみ（初期は閉じ）で上部を圧縮。
- 要対応統計行・右詳細ペイン（固定ヘッダー/Documents/Context/Diagnostics/保存時HEAD/保存コンテキストNote 等）は維持。
